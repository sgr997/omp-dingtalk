# release 钉钉确认回执修复

需求：主动 release 后恢复钉钉释放确认，同时保持后续自动通知停止。

## 受影响路径与状态

- 首次使用、未接管：release 仅停止本会话通知，无接管可解除，不产生虚假释放回执。
- 已接管及已有机器人配置：先立即关闭入站、取消待处理工作、保存停止推送状态，再向刚释放的机器人排队发送一次确认。命名机器人切回 default 不改变回执目标。
- 旧版升级、缺字段：沿用上一修复的 notificationsReleased 迁移；回执不新增持久化字段。
- 重复操作：重复 release 保留停止状态，不重复发送，也不撤销仍排队的首次确认。
- 来源切换、回退：内部释放、配置切换或被抢占不主动发送释放回执；新接管、配置变更或其他本地持有者使未发送的旧回执失效。
- 失败恢复：发送失败仍保持已释放，终端报告确认失败；成功 takeover 后才恢复自动通知。
- 队列拥堵：确认复用限速队列，命令不等待确认发送。

## 复现与验证

修改前，命令集成夹具预期释放回执 1 条，实际 0 条（/tmp/omp-release-receipt-red.log）。
