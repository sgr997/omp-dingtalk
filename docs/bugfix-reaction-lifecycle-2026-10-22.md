# reaction 生命周期闭环修复

用户路径：钉钉发送自由文本后，机器人先为原消息添加 👀；OMP 完成或失败后，原消息应只保留一个终态 reaction。

## 状态覆盖

- 首次使用与已有配置：不新增配置或迁移字段。
- 正常完成：撤回 👀、⚡ 或 📋 等原状态，再添加 `✅ 已完成`。
- 执行失败：撤回原状态，再添加 `❌ 失败`。
- 重复完成事件：相同终态幂等，不重复调用接口。
- 并发：👀 尚未返回就收到完成事件时，对同一条消息串行执行，避免结束后旧表情才出现。
- 来源切换与接管失效：沿用原有效性检查，失效请求不再修改 reaction。
- API 失败：只有撤回成功后才更新本地状态；撤回失败不继续叠加终态，避免把失败响应误记为闭环。
- 长会话：本地状态最多保留 500 条，防止进程常驻时无限增长。

## 缺陷证据

修复前运行：

```text
bun test/regressions/omp-reaction-lifecycle.ts
actual: ["👀", "✅"]
expected: ["✅ 已完成"]
```

原因有两项：旧实现只调用 emotion/reply 追加 ✅，从未调用 emotion/recall 撤回 👀；同时所有 reaction 都错误复用了 👀 的 `2659900 / im_bg_1` 元数据。

修复后的集成夹具使用真实插件事件、Stream 入站解析与发送器代码，只模拟网络端点，并断言调用顺序及最终服务端状态。不会向真实钉钉发送消息。

边界夹具验证慢速 👀 请求、撤回 HTTP 503 后重试，以及撤回期间 release/接管失效时不再追加终态。此处重试指再次请求同一终态，不是自动无限重试。真实钉钉客户端显示仍待更新并重启 OMP 后验收。
